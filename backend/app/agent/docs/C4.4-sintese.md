# Camada 4.4 — Síntese da Resposta

## 1. Visão geral

A camada **4.4 — Síntese da Resposta** transforma o resultado de uma consulta SQL já executada em uma resposta clara, em português, para usuários de negócio que não conhecem SQL.

Fluxo:

```text
Pergunta do usuário
        ↓
Input Guardrail
        ↓
4.1 — Geração de SQL
        ↓
4.2 — SQL Guardrail
        ↓
4.3 — Execução no banco
        ↓
4.4 — Síntese
        ↓
Camada 5 — Output Guardrail
```

A 4.4 não executa SQL e não decide o que consultar.

---

## 2. Responsabilidades

A camada é responsável por:

- tratar resultado vazio sem chamar a IA;
- montar o prompt com pergunta, SQL e resultado;
- limitar o volume de linhas enviadas ao modelo;
- sinalizar resultado parcial ou truncado;
- pedir uma resposta estruturada e fiel aos dados;
- declarar as suposições usadas na resposta.

Não é responsabilidade da 4.4:

- gerar ou validar SQL;
- executar consultas;
- verificar deterministicamente os números da resposta (Camada 5);
- controlar providers e fallback (Camada 3).

## 3. Arquitetura

```text
app/agent/
├── answer_synthesizer.py
├── prompts/synthesis/
│   ├── system.md
│   ├── security.md
│   ├── output_contract.md
│   └── loader.py
└── schemas.py
```

A interface principal é:

```python
synthesize_answer(question, sql, result)
```

e retorna `(SynthesisResult | None, attempts, provider_error)`, o mesmo padrão da 4.1.

O fallback entre providers é reaproveitado de `run_with_fallback()`.

---

## 4. Contratos

### Entrada: `QueryExecutionResult`

```text
columns    → nomes das colunas
rows       → linhas retornadas
row_count  → total de linhas do resultado
truncated  → se o resultado foi cortado na execução
```

O contrato é provisório e deve ser alinhado com a 4.3.

### Saída: `SynthesisResult`

```text
status       → ANSWERED | NO_DATA
answer       → resposta ao usuário (obrigatória)
assumptions  → suposições relevantes (lista, pode ser vazia)
```

---

## 5. Decisões tomadas

### Resultado vazio

Resultado sem linhas gera uma mensagem fixa (`NO_DATA`), em código. A IA não é chamada. Isso reduz custo e latência e elimina o risco de invenção.

### Limite de linhas no prompt

No máximo **50 linhas** são enviadas ao modelo. Se houver mais, o prompt marca o resultado como parcial e o modelo deve avisar o usuário.

### O modelo não calcula

O prompt proíbe somas, médias e percentuais que não estejam no resultado. Isso mantém a resposta verificável pela Camada 5, que confere os números do texto contra as linhas retornadas.

### Dados como conteúdo não confiável

Valores vindos do banco podem conter texto malicioso. Por isso:

- o resultado é serializado em JSON;
- o caractere `<` é escapado, para que um valor não consiga fechar as tags do prompt;
- o prompt de segurança instrui o modelo a tratar dados apenas como conteúdo.

### Declaração de suposições

O modelo registra em `assumptions` o período, filtros e definições de métrica relevantes, para auditoria.

## 6. Testes

### Determinísticos (`pytest`, sem chamada real)

- contratos (`QueryExecutionResult`, `SynthesisResult`);
- loader dos prompts;
- resultado vazio sem chamada ao provider;
- limite de 50 linhas e marcação de parcial;
- tentativa de fechar tags do prompt;
- erro de provider propagado;
- saída inválida rejeitada.

### Reais (`RUN_LLM_INTEGRATION=1`)

- fidelidade aos valores do resultado;
- aviso de resultado parcial;
- resistência a instruções presentes nos dados;
- recusa de inventar um cálculo que o resultado não traz.

Execução:

```powershell
$env:RUN_LLM_INTEGRATION="1"
python -m pytest tests/agent/integration/test_answer_synthesis_real.py -v -s
```

Os testes reais são marcados como `SKIPPED` quando todos os providers estão indisponíveis.
